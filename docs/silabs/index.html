A $40 Silicon Labs chip that proves what code it runs — on-chain

Live attestation from a real SiMG301 Secure Vault, verified in your browser against a contract on Base Sepolia.

This is a Silicon Labs SiMG301M104LIL — a Series 3 “Secure Vault High” wireless SoC, the first chip publicly listed at PSA Certified Level 4. On the same die as its Cortex‑M33 sits a hardware Secure Element. At Silicon Labs' factory the SE is given its own ECDSA P‑256 keypair; the private half is sealed in on‑die OTP and never leaves the chip.

That factory key lets the chip sign a PSA attestation token (an IETF EAT, COSE_Sign1 / ES256) that says, in effect: “I am this specific Silicon Labs part, and this is the hash of the code I booted.” The token's signing key chains to a root certificate Silicon Labs publishes openly — so anyone can check it, no NDA, no vendor portal. We do that check, and the signature check, inside a smart contract.

What this proves — and what it doesn't (yet)

proven The token was signed by a genuine Silicon Labs SE whose key chains to the published root; the signature verifies on‑chain; the chip is a live registry member.

dev mode Secure boot is not yet enabled on this part (no irreversible OTP burn), so the measurement is the SE's own firmware hash (PRoT), not the application hash. With secure boot on, the same token carries an ARoT entry = SHA‑256 of the operator's app — and nothing else in this pipeline changes. The verifier flags dev‑mode explicitly rather than hiding it.

Trust model: you trust Silicon Labs as the silicon manufacturer (the root of the cert chain). You do not trust the operator, a cloud, or any server — the check runs in a public contract.

Hardware bring‑up, the verifier, and the cross‑platform interop write‑up live in the tee‑interop repo (contracts/SilabsVerifier.sol, tools/silabs/build_proof.py, INTEROP-silabs-dstack.md). Attestation token and certificates captured from real silicon.
