A TEE network with no center of trust

Wildly different trusted hardware — a datacenter VM, a CI runner, a $40 microcontroller, a re-flashed phone — each proves what code it runs to one neutral contract on Base. Once verified, they become peers.

verify in your browser — click a green node on-chain adapter reference verifier

Every node runs different silicon with a different root of trust — Intel, AMD, Google's Titan M2, a Silicon Labs secure element, even GitHub's Sigstore CI identity. None trust each other a priori. What they share is one smart contract: each platform plugs in as an IVerifier, submits its native attestation, and the contract checks the signature against that vendor's published root. The registry itself has zero platform-specific code.

Once verified, a member can hand ECIES-encrypted secrets to any other verified member via onboard() — no shared KMS, no central authority, no operator to trust. The chain is the only thing they have in common. A GitHub Actions job proving which workflow built an artifact and a $40 microcontroller proving its firmware hash end up as equal citizens of the same registry.

About

Members register their TEE-attested identity once; verified peers exchange ECIES-encrypted secrets via onboard() without any shared KMS infrastructure. See the ERC-733 write-up for the interface design and the Sparsity 8004 comparison for how this differs from the existing reference impl.
