1 · The demo concept

The MCU is the TLS endpoint; the host is just an untrusted byte pipe. The Anthropic API key lives only on the chip. Every response comes back with a PSA attestation token whose nonce = SHA-256 of the TLS transcript commitment, so a third party can check: this exact response came from api.anthropic.com, fetched by this exact measured firmware, on a genuine SiLabs die — and the key never left the chip.

Honest framing: this is attested TLS (a TEE oracle, à la Town Crier) — not zero-knowledge. There is no ZK proof; the trust reduction is "chipmaker + measured firmware" instead of "the host operator". The IAT's 32-byte nonce field carries a hash commitment to the transcript, not the transcript itself.

3 · What each chain actually proves

ClaimDev mode (today)Production
Genuine SiLabs die, SE-held key (can't be exfiltrated or emulated)✓✓
Secure boot: only firmware signed by our key boots✓ (burned)✓
ARoT claim = SHA-256 of the app that actually booted✓✓
Attacker with the board can't read the API key✗ — SWD is open: attach a debugger after boot, dump RAM/flash✓ debug locked
Attacker with the board can't puppet the measured app at runtime✗ — debugger can hijack execution while ARoT still reads clean✓
Attacker can't wipe & reprovision the device as "fresh"✗ — device erase enabled✓ erase disabled
Verifier can tell the difference remotely✓ — lifecycle claim 0x4001 vs 0x3xxx is inside the signed token; nothing is hidden
Unlike the Pixel (lock/unlock/reflash at will), the SiMG301's debug lock + erase-disable are one-way fuses — there is no "unlock, iterate, re-lock" loop. So we stay in dev mode for development, and the token honestly advertises that. The production column is exactly two fuse burns plus one verifier policy line away.

5 · Build plan for the proxy demo

  1. Firmware: extend taskboard-runner — mbedTLS client over a serial-framed TCP socket (host relays), pinned CA for api.anthropic.com, request template with the key inserted on-chip, IAT over sha256(request-sans-key ‖ response).
  2. Key sealing: Anthropic API key imported once into Secure Vault wrapped storage (never in the host relay or logs).
  3. Host relay: ~50-line Python: TCP ↔ /dev/ttyACM0 byte pump. Untrusted by construction.
  4. Verifier: existing offline check + SilabsVerifier on-chain view call; add the lifecycle policy line and show it rejecting today's 0x4001 token when run in "production policy" mode — the two columns above, executable.
