The actual CI run that signed the attestation below — an ephemeral GitHub-hosted VM running amiller/github-zktls at commit 2ed50fd9, its output bound by a Sigstore certificate.

GitHub Actions runs your workflow in an isolated, ephemeral VM, and Sigstore issues a short-lived certificate — from its public Fulcio CA — that binds the signed output to the exact identity of the run: the repository, the commit SHA, and the workflow file. Together these are the core properties of a trusted execution environment: isolated execution plus an unforgeable attestation tying an output to specific code.

We compress that Sigstore bundle into a zero-knowledge proof (Noir / Honk) so it verifies on-chain for about 3M gas. Crucially, the attestation binds to the commit SHA, not to who owns the repo — so anyone can fork the workflow and produce valid proofs. Deployment is permissionless in the same sense a smart contract is: no developer, oracle, or committee sits in the middle.

The runner presents its GitHub OIDC token to Sigstore's Fulcio CA, which issues an ephemeral X.509 cert whose identity fields are the repo, commit SHA and workflow. That cert signs the artifact. The ZK proof attests "a Fulcio-issued certificate for this repo and commit signed this artifact" without revealing the full bundle — and the contract checks it against Sigstore's published root.

Bound to code, not ownership. The proof commits to the commit SHA, so it says which workflow at which revision ran — independent of who triggered it. Fork the repo, run the same workflow, and you get an equally valid proof under your own commit. That is what makes it permissionless.

Trust model: you trust GitHub Actions for execution isolation and Sigstore as the certificate root (both public, both transparency-logged). You do not trust the operator, a server, or any developer — the check runs in a public contract, and anyone can reproduce the proof by forking the workflow.
